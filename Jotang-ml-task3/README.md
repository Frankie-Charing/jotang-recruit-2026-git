## 趁热打铁

### 1. 前向传播时为什么要保存每一层的输入或输出？反向传播会在哪里用到它们？这和显存有什么关系？

反向传播要用链式法则。例如对 `ReLU` 的反向传播需要知道**前向时的输入 z1 是正还是负**（`relu'(z)=1(z>0)`）；对线性层 `z = xW + b`，`dL/dW = xᵀ·dL/dz`，需要**前向时的输入 x**。所以前向时要把这些中间结果保存下来，反向时才能取用。

这和显存的关系：保存的中间激活越多、batch 越大，占用显存就越多。深度学习里常说的“显存不够”，很大一部分就是被这些**中间激活**占掉的。这也是后来出现 activation checkpointing（用重算换显存）的原因。

### 2. 链式法则怎样把损失函数的梯度传回第一层权重？结合计算图说明。

我的两层网络计算图是：

`X → z1(=XW1+b1) → a1(=ReLU(z1)) → z2(=a1W2+b2) → p(=Sigmoid(z2)) → L`

梯度从后往前传：

- 先求 `dL/dz2 = p - y`（BCE 与 Sigmoid 合并后的漂亮结果）；
- `dL/dW2 = a1ᵀ · dL/dz2`，`dL/db2 = Σ dL/dz2`；
- `dL/da1 = dL/dz2 · W2ᵀ`；
- `dL/dz1 = dL/da1 ⊙ relu'(z1)`；
- `dL/dW1 = Xᵀ · dL/dz1`，`dL/db1 = Σ dL/dz1`。

每一步都只依赖“上一层传来的梯度”和“本层前向保存的输入”，于是损失就能一步步传回第一层权重 W1。

### 3. 二元交叉熵与 Sigmoid 配合后，loss 对 logit 的梯度是什么？为什么方便？

设 `p = σ(z)`，BCE 损失 `L = -[y ln p + (1-y) ln(1-p)]`，则：

`dL/dz = p - y`

推导思路：`dL/dp = -y/p + (1-y)/(1-p)`，而 `dp/dz = p(1-p)`，两者相乘化简即得 `p - y`。

它“漂亮”在于：梯度直接等于**预测值与标签之差**，没有 Sigmoid 导数里那种会饱和的 `p(1-p)` 因子，也不会在 p 接近 0/1 时出现除以极小数的不稳定。因此数值稳定、实现简单。

### 4. NumPy 梯度与 PyTorch 梯度出现差异时，怎样定位问题？

我会按顺序排查：

1. **形状对齐/转置**：先检查每个梯度形状是否与参数一致（`dL/dW` 必须与 W 同形状），转置方向最容易写反。
2. **广播**：bias 的梯度是对 batch 维求和；如果 NumPy 里少做或做错 sum(axis=0)，会立刻不一致。
3. **损失求平均方式**：BCE 是否除以了 batch size？`mean` 与 `sum` 差一个常数倍，要确认 PyTorch 的 `binary_cross_entropy` 默认是 mean。
4. **激活函数导数**：ReLU 在 0 处的导数值、Sigmoid 是否忘记乘 `p(1-p)` 等。
5. 最后用**数值梯度**（给参数加一个小扰动 δ，看损失变化 `(L(θ+δ)-L(θ-δ))/(2δ)`）单独验证某一项，定位是哪个公式错。

### 5. 完成两次验证后，怎样理解 loss.backward()？

`loss.backward()` 实际上替我们做了三件事：

1. **保存前向图**：PyTorch 在每次张量运算时记录“谁由谁算出来”（autograd 动态图）。
2. **按链式法则反向传播**：从 loss 出发，沿着计算图从后往前自动求出每个 `requires_grad=True` 参数/张量的梯度。
3. **把梯度累加到 `.grad`**：结果存到对应张量的 `.grad` 属性里，供优化器取用。

我自己手推了两遍之后，对“它只是把链式法则自动化了”这一点有了实感：我们做的事，本质上就是沿着计算图逐层求导。

### 6. 遇到的报错 / 不理解的点记录

- 一开始把 `dL/dz1 = dL/da1 ⊙ relu'(z1)` 里的逐元素乘写成了矩阵乘，导致形状对不上。理解后改成 Hadamard 积（`*`），问题解决。
- 对 bias 的梯度起初忘了对 batch 维求和，单样本时看不出来，换成 batch=4 后与 PyTorch 出现差异，排查后修正。
- 不理解“为什么 BCE 梯度是 p-y”：自己把 `dL/dp` 与 `dp/dz` 乘起来化简了一遍就清楚了。
